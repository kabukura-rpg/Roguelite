# 株クラ

親フォルダの `kabukura_roguelite_game_spec.md` を実装した、20年完結の投資判断ローグライトです。既存の売買・相場システムを維持し、戦略カードとデッキ構築を追加しました。

## 起動

Node.js 22.13以上（推奨24）を使用してください。

```sh
npm install
npm run dev
```

ローカルURLは起動時に表示されます。開発サーバーを止めるとローカルプレビューは終了します。

```sh
npm test
npm run typecheck
npm run build
```

ビルドは静的出力 `dist/client/` を生成します。サーバー、ログイン、実市場APIはゲーム自体には不要です。途中セーブ・永続記録は実装しません。

## GitHub Pagesへの公開

公開先は **https://kabukura-rpg.github.io/Roguelite/**、リポジトリは `kabukura-rpg/Roguelite` です。

1. GitHubのリポジトリで **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択します。
2. この変更をリポジトリの `main` にコミット・pushします。
3. **Actions → Deploy game to GitHub Pages** が成功すると公開されます。`Run workflow` からの手動実行にも対応します。

ルートの `.github/workflows/deploy-pages.yml` が `game/` でNode.js 24、`npm ci`、ゲームテスト、型チェック、静的ビルドとアセット検証を実行し、**`game/out/`** をPagesにデプロイします。`game/` やリポジトリ全体をそのまま公開する構成ではありません。追加のトークン登録は不要で、Actionsの `GITHUB_TOKEN` とOIDCを使用します。

公開用ビルドは `game/` 内で実行できます（macOS / Linux）。

```sh
npm ci
npm run build:pages
```

ローカル開発の `npm run dev` と従来の `npm run build` は引き続きNext.js互換のvinextを使います。Pages用の `build:pages` はNext.js 16.3.4の `next build --webpack` を使い、`out/` にHTML・CSS・JavaScript・publicファイルを静的出力します。ゲームロジックとスタイルは共通です。Next.js用の生成キャッシュは `.next-pages/`、型チェック設定は `tsconfig.pages.json` に分け、ローカルvinextの生成型との衝突を防いでいます。`npm start` は従来のWorker用で、Pages出力のプレビューには使いません。

`next.config.ts` の `output: 'export'`、`trailingSlash: true`、`images.unoptimized: true` によりサーバー不要で配信します。Pagesビルド時だけ `GITHUB_PAGES=true` で `basePath: '/Roguelite'` を設定します。CSS・JSはNext.jsがprefixを付与するため、別の `assetPrefix` は不要です。`public/` のfaviconには `NEXT_PUBLIC_BASE_PATH` を明示的に付けています。通常のローカル開発URLは `/` のままです。

`scripts/verify-pages.mjs` はトップページ・404・`.nojekyll` の存在と、HTML・CSSから参照する同一サイト内のアセットが `/Roguelite/` 内にあり、実ファイルとして出力されていることを検査します。`npm run verify:pages` でも再実行できます。ブラウザ操作のテストではありません。

`game/` は親リポジトリに通常ディレクトリとして登録されています。Gitの `160000`（gitlink）エントリ、`game/.git`、`.gitmodules` はありません。Actionsでもサブモジュールの取得を無効にし、gitlinkになっていないことと `game/package.json`・`game/app/page.tsx` の追跡を確認します。今後 `game/` 内で `git init` や `git submodule add` は行わず、親リポジトリから `git add game` で管理してください。

参考: [Next.js static export](https://nextjs.org/docs/app/guides/static-exports)、[basePath](https://nextjs.org/docs/app/api-reference/config/next-config-js/basePath)、[GitHub PagesのActions設定](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 実装

- `lib/game/data.ts`: 設定、5資産、10相場、リターン表、ランク境界
- `lib/game/engine.ts`: シード付き乱数、抽選補正、状態遷移、売買、再投資、配当、手数料、最大DD、称号
- `lib/game/cards.ts`: 8戦略カード、初期デッキ、山札・手札・捨て札、独立したシード付きシャッフル、使用集計
- `components/game/strategy.tsx`: 手札選択、デッキ一覧、報酬、カード購入・削除、カード使用結果
- `app/page.tsx`: 既存画面＋カード報酬、遊び方、全履歴、SVG資産グラフ
- `app/globals.css`: 共通テーマとタイトル・成績画面
- `app/board.css`: ビューポートに収まるHUD、相場、縦長手札、進行ボタン
- `components/game/board.tsx`: 相場盤面、コンパクトHUD、年末結果、タブ式ショップ、カード報酬
- `tests/engine.test.ts`: 仕様TC01〜10、手数料・整数丸め・連打・称号・ランク・200シード完走等の既存20テスト
- `tests/cards.test.ts`: 8カード×3コマンドの計算、効果の期限、報酬・購入・削除、100シードの完走、デッキ整合性

同じ `?seed=12345` とすると同じ相場系列を再現します。`?debug=1&seed=12345` は抽選重み、前後資産、判断、最大DD、証券会社間隔を表示し、予報画面で相場を強制できます。デバッグ指定時のみ有効です。

売却と再投資の端数は、移動額を四捨五入し反対側から同額を引くことで1円の増減を防ぎます。証券会社は最初の訪問を3〜5年目、以後3〜5年の間隔とし、変更手数料によるDDも記録します。変更手数料が総資産を超える場合は残額全額を差し引いてGAME OVERとなります。`crashCount` は通常暴落、`severeCrashCount` は歴史的大暴落を個別に数え、画面の暴落経験では合算します。

任意対応のWebMCP（`document.modelContext`）には `read_kabukura_game` と `play_kabukura_action` を登録します。未対応ブラウザでは通常のUIだけで動作します。ローカルブラウザでWebMCPによる開始・投資先選択・相場公開と、通常UIによるカード選択・詳細表示・進行確定を確認しています。

## 通常ターンの進行とカード効果

市場予報 → 相場公開 → 戦略カードを0〜1枚選択 → 相場結果 → 資産変動、の順で進みます。通常画面とWebMCPは `RESOLVE` で進行を確定し、狼狽売り／ホールド／買い増しの追加選択はありません。

相場公開時は相場の名前・説明とリスクのヒントだけを表示します。確定リターンや予想総資産は表示せず、騰落率・カード適用後のリターン・資産差額は進行確定後に公開します。相場抽選・リターン表・シードによる再現性は従来通りです。今回は騰落率のランダム化は行っていません。

1. 5枚までドローし、必要ならショップへ。市場予報から相場を公開します。
2. 手札を0〜1枚選びます。選択・解除・リバランス先変更は進行確定まで自由です。
3. 進行確定時、リバランスは変更手数料を支払って投資先を変更。現金確保は投資資産の20%を先に現金化します。
4. ドルコスト平均法は現金の75%、逆張りは現金の50%をカード単体で追加投資します。他のカードとカードなしでは現在の配分を維持します。
5. 相場にカード補正を適用。分散投資は下落30%軽減、損切りは下落−25%が下限、レバレッジは利益・損失1.8倍です。既存の逆張り待機効果は次に保有資産がプラスになる相場で一度だけ1.3倍となります。
6. 高配当株の1.5%と戦略配当金の1%を現金へ。配当金は使用年を含む3年間、重ね掛けは期間を3年延長します。
7. 逆張りを暴落・歴史的大暴落で使った場合、次回分の効果が待機します。カードなしでも継続効果は適用します。
8. 履歴を記録し、未使用を含む手札すべてを捨て札へ。3年ごとのカード報酬、ショップ、20年後の成績へ進みます。

暴落を含む既存10相場は通常のカード攻略対象です。これとは別に年末の突発イベントを追加しました。旧 `DECIDE` とプレビュー計算は計算互換用に残していますが、通常UIとWebMCPからは呼び出しません。

獲得カードは捨て札に入り、次のシャッフルから抽選対象になります。同種カードもインスタンスIDで区別し、削除は選択した1枚だけです。手札・デッキが0枚でも「このまま進む」で進めます。ショップは既存の価格・現金優先支払い・退出時の手札補充を維持しています。

`tests/normal-turn.test.ts` はカード単体での追加投資、選択解除、空の手札、二重処理防止、継続進行と100シードの20年完走を検証します。既存の計算・売買・ショップ・デッキのテストも維持しています。

## ローカル用ゲーム盤レイアウト

プレイ中は画面の高さ（100dvh）に合わせたHUD・盤面・メニューの3段構成です。PCでは下部の縦長手札の右に進行ボタンを置き、幅が狭い場合は手札の下に置きます。カード選択で浮き上がりと金色の発光を表示し、動きを減らす設定にも対応します。

資産グラフ・投資額の詳細・履歴は下部の「記録」から開きます。年末結果は簡潔なRESULT表示と詳細ダイアログに分け、リバランス先の選択もダイアログに移しました。ショップは装備変更／カード購入／カード削除のタブ式で、退出ボタンは常時表示します。

スマホでは手札・報酬カードを横にスワイプします。小さい画面や文字拡大では必要に応じて盤面の一部をスクロールでき、操作を切り捨てません。成績画面と詳細パネルには縦スクロールを許可しています。今回のレイアウト改修はローカル確認用で、サイトへのアップロード・公開更新は行いません。

## 年末の突発イベント

通常相場のRESULTにある「年末の出来事を確認」で発生判定を行います。イベントがなければ報酬／次の年へ、発生すれば選択 → 結果 → 報酬／次の年へ進みます。20年目も判定し、最後のイベント結果を反映してからランク・称号を計算します。資産が尽きた場合は結果確認後にGAME OVERです。

- 発生可能な年の基本確率は30%。前年に発生した場合は必ず休みます。そのため全20年に対する実際の発生率は30%より低くなります。
- 残り年数と連続禁止を考慮し、20年完走時は最低4回を保証します。途中で資産が尽きたプレイは保証対象外です。同一イベントは1回までです。
- 市場・カード抽選とは独立したシード付き乱数を使用します。発生判定を二重実行せず、不正な選択や連打で再抽選できません。

15種類は `lib/game/incidents.ts` で管理します。

| 分類 | 内容 | 処理 |
| --- | --- | --- |
| 市場ショック（3種） | 信用不安、緊急政策、薄商いの急変 | この画面だけ狼狽売り／ホールド／買い増しを表示。選択後に騰落率を抽選。売りは急変前に投資90%を現金化、買い増しは現金50%を投入。翌年の再投資は既存の30%ルールを使用。 |
| 生活トラブル（6種） | 怪我、家電、水漏れ、冠婚葬祭、ペット、引っ越し | 4.5万〜11万円の必要経費。現金優先、不足額のみ投資資産を強制売却。売却手数料・借金はなし。支払不能なら資産を0円で止めてGAME OVER。 |
| 日常／チャンス（6種） | 儲け話、落とし物、休日、勉強会、セール、臨時収入 | リスクと費用を文章で明示。任意の出費は手元現金が必要で、足りない選択肢は選択不可。無料で進める選択肢を必ず用意。 |

日常の報酬は現金、カード（捨て札へ）、次回の詳細予報、次の通常相場の下落半減です。詳細予報では資産ごとの方向感を示し、正確な騰落率は開示しません。下落半減は次の通常相場に1回適用し、上昇でもその年で終了。継続効果は重複せず、通常相場の処理で消費します。20年目は次回効果・獲得カードの使用機会がないことを表示します。市場ショックは年間の配当・戦略効果・通常相場の履歴を二重処理しません。

突発イベントの支払額・強制売却額・騰落率・獲得内容を結果画面と記録に表示し、資産グラフ・最大DD・最終資産にも反映します。WebMCPは `incident_choice`（`choiceId`）と `incident_next` に対応し、選択前の市場ショックの確定結果は公開しません。

`tests/incidents.test.ts` では2,000通りの発生スケジュール、支払優先順位、破産、選択ガード、ショックの売買順序、効果の期限、報酬・最終年の順序、履歴・グラフの整合性を検証します。

## UIの微調整と確認

相場公開後はアイコン・相場名・説明・市場リスクを中央にまとめています。正確な騰落率は進行確定後のRESULTだけに表示します。カードを使わない進行は「このまま進む」に統一しました。

目標額は `GAME_CONFIG.targetAssets`（300万円）を共有し、総資産HUDに細い進捗バーと達成率を表示します。カード内は短い効果だけに絞り、ホバー時の説明と選択後の「詳細」から全文を確認できます。RESULTでは使用戦略・保有資産の騰落率・総資産の前後を表示します。

PC（1440×900）、ノートPC（1366×768）、タブレット（820×1180・768×1024）、スマートフォン（390×844・375×667）をローカルブラウザの表示サイズ切り替えで確認しました。通常の相場・手札画面とRESULTで文言の重なりやページ全体の縦スクロールがないこと、長いカード名の折り返し、選択・詳細表示を確認しています。実機検証ではありません。既存61テスト・lint・Pages静的ビルドとアセットパス検証も通過しています。
