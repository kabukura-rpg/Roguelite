# 株クラ

20年完結の投資判断ローグライトです。開始時に固定する **CORE**、4年ごとに育てる **PORTFOLIO**、毎年の短期戦略を組む **DECK** の3層で投資ビルドを育てます。このREADMEを現行仕様とし、親フォルダの `kabukura_roguelite_game_spec.md` と矛盾する場合はREADMEと現在の実装を優先してください。

## 起動

Node.js 22.13以上（推奨24）を使用してください。

```sh
npm install
npm run dev
```

ローカルURLは起動時に表示されます。開発サーバーを止めるとローカルプレビューは終了します。

```sh
npm test
npm run typecheck
npm run build
```

ビルドは静的出力 `dist/client/` を生成します。サーバー、ログイン、実市場APIはゲーム自体には不要です。進行中のプレイはブラウザの `localStorage`（キー `kabukura-save`）に自動保存し、タイトルの「続きから」で再開できます。保存はクリア・GAME OVER・新規開始で消えます。保存が使えない環境（プライベートウィンドウなど）でも通常どおり遊べます。

## GitHub Pagesへの公開

公開先は **https://kabukura-rpg.github.io/Roguelite/**、リポジトリは `kabukura-rpg/Roguelite` です。

1. GitHubのリポジトリで **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択します。
2. この変更をリポジトリの `main` にコミット・pushします。
3. **Actions → Deploy game to GitHub Pages** が成功すると公開されます。`Run workflow` からの手動実行にも対応します。

ルートの `.github/workflows/deploy-pages.yml` が `game/` でNode.js 24、`npm ci`、ゲームテスト、型チェック、静的ビルドとアセット検証を実行し、**`game/out/`** をPagesにデプロイします。`game/` やリポジトリ全体をそのまま公開する構成ではありません。追加のトークン登録は不要で、Actionsの `GITHUB_TOKEN` とOIDCを使用します。

公開用ビルドは `game/` 内で実行できます（macOS / Linux）。

```sh
npm ci
npm run build:pages
```

ローカル開発の `npm run dev` と従来の `npm run build` は引き続きNext.js互換のvinextを使います。Pages用の `build:pages` はNext.js 16.3.4の `next build --webpack` を使い、`out/` にHTML・CSS・JavaScript・publicファイルを静的出力します。ゲームロジックとスタイルは共通です。Next.jsの中間生成物は既定の `.next/`、静的公開ファイルは `out/` に出力します。Pages用の型チェックには `tsconfig.pages.json` を使い、`.next/types/` を参照します。`output: 'export'` とカスタム `distDir` を組み合わせると、`distDir` が静的出力先になるため、ここでは指定しません。`npm start` は従来のWorker用で、Pages出力のプレビューには使いません。

`next.config.ts` の `output: 'export'`、`trailingSlash: true`、`images.unoptimized: true` によりサーバー不要で配信します。Pagesビルド時だけ `GITHUB_PAGES=true` で `basePath: '/Roguelite'` を設定します。CSS・JSはNext.jsがprefixを付与するため、別の `assetPrefix` は不要です。`public/` のfaviconには `NEXT_PUBLIC_BASE_PATH` を明示的に付けています。通常のローカル開発URLは `/` のままです。

`scripts/verify-pages.mjs` は `.next/export-detail.json` で直近exportの成功と出力先が `out/` であることを確認したうえで、トップページ・404・`.nojekyll` の存在と、HTML・CSSから参照する同一サイト内のアセットが `/Roguelite/` 内にあり、実ファイルとして出力されていることを検査します。`npm run verify:pages` でも再実行できます。ブラウザ操作のテストではありません。過去の `.next-pages/` 出力設定では、ローカルに残った古い `out/` を検証して成功する問題がありました。出力先の確認により、この誤検知も防止します。

`game/` は親リポジトリに通常ディレクトリとして登録されています。Gitの `160000`（gitlink）エントリ、`game/.git`、`.gitmodules` はありません。Actionsでもサブモジュールの取得を無効にし、gitlinkになっていないことと `game/package.json`・`game/app/page.tsx` の追跡を確認します。今後 `game/` 内で `git init` や `git submodule add` は行わず、親リポジトリから `git add game` で管理してください。

参考: [Next.js static export](https://nextjs.org/docs/app/guides/static-exports)、[basePath](https://nextjs.org/docs/app/api-reference/config/next-config-js/basePath)、[GitHub PagesのActions設定](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

同じ `?seed=12345` とすると同じ相場系列を再現します。`?debug=1&seed=12345` は抽選重み、前後資産、判断、最大DD、証券会社間隔を表示し、予報画面で相場を強制できます。デバッグ指定時のみ有効です。

売却と再投資の端数は、移動額を四捨五入し反対側から同額を引くことで1円の増減を防ぎます。証券会社は最初の訪問を3〜5年目、以後3〜5年の間隔とし、カード購入・削除によるDDも記録します。費用が総資産を超える場合は残額全額を差し引いてGAME OVERとなります。`crashCount` は通常暴落、`severeCrashCount` は歴史的大暴落を個別に数え、画面の暴落経験では合算します。

任意対応のWebMCP（`document.modelContext`）には `read_kabukura_game` と `play_kabukura_action` を登録します。未対応ブラウザでは通常のUIだけで動作します。ローカルブラウザでWebMCPによる開始・投資先選択・予報表示と、通常UIによるカード選択・詳細表示・進行確定を確認しています。

## 通常ターンの進行とカード効果

市場予報 → 戦略カードを0〜1枚選択 → 進行確定 → 相場・騰落率抽選 → カード効果・資産変動 → RESULT、の順で進みます。通常画面とWebMCPは `RESOLVE` で進行を確定し、狼狽売り／ホールド／買い増しの3択は年末の市場ショック時だけに出ます。

カード選択時には景気・市場心理・金利・ボラティリティの観測材料だけを表示します。相場名・市場リスク・確定リターン・予想資産は表示しません。実際の相場と騰落率は `RESOLVE` の中で初めて抽選され、RESULTで予報との違い・カード適用後のリターン・資産差額を公開します。

1. 5枚までドローし、必要ならショップへ。市場予報を見て、そのままカードを選べます。
2. 手札を0〜1枚選びます。選択・解除は進行確定まで自由です。コア資産は変更できません。
3. 進行確定時、現金確保は投資資産の20%を先に現金化します。
4. ドルコスト平均法は現金の75%、逆張りは現金の50%をカード単体で追加投資します。他のカードとカードなしでは現在の配分を維持します。
5. 相場にカード補正を適用。分散投資は下落30%軽減、損切りは下落−25%が下限かつ上昇+14%が上限、レバレッジは利益・損失2倍です。既存の逆張り待機効果は次に保有資産がプラスになる相場で一度だけ1.3倍となります。
6. 高配当株に配分された投資額の1.5%と戦略配当金の1%を現金へ。「配当再投資」を取得している場合だけ、高配当株の配当の50%を投資資産へ戻します。戦略配当金は対象外で、従来どおり使用年を含む3年間、重ね掛けは期間を3年延長します。
7. 逆張りを暴落・歴史的大暴落で使った場合、次回分の効果が待機します。カードなしでも継続効果は適用します。
8. 履歴を記録し、未使用を含む手札すべてを捨て札へ。年末の突発イベント → 対象年のポートフォリオ成長 → 対象年のカード報酬 → 翌年の順で進みます。ショップは従来の訪問間隔を維持します。

## ポートフォリオ成長

初期資産100万円（投資80万円・現金20万円）、全20年間、目標300万円は従来どおりです。

|層|役割|獲得・変更の機会|
|---|---|---|
|CORE|バランス型＝オルカン、成長型＝S&P500、攻撃型＝NASDAQ100|開始時に1つ選び、20年間固定|
|PORTFOLIO|サテライトと長期投資方針による恒久成長|4・8・12・16年目終了時|
|DECK|毎年0〜1枚使う短期戦略|既存のカード報酬、ショップでの購入・削除|

高配当株・ゴールド・債券はサテライトです。成長イベントで追加すると投資資産の20%を配分します。現金を除く比率は、開始時100%、1枠で80/20、2枠で60/20/20。最大2枠で同じ資産は重複取得できません。MVPでは各年ともこの固定比率を使用し、手動調整や値動きによる比率のずれ、入れ替え費用は扱いません。

通常相場のリターンは `portfolioReturn()` で各資産の比率×リターンを合計し、その後で既存の戦略カード補正を適用します。市場ショックも既存の資産別感応度を同じ比率で加重平均します。3択の売買順・乱数抽選は維持しています。既存の資産別リターン表、配当率、カード数値は変更していません。

高配当株の配当は相場適用後の投資資産×高配当株比率×既存配当率1.5%を四捨五入します。通常は全額現金へ入ります。「配当再投資」取得後のみ50%を四捨五入して投資資産へ戻し、残額を現金に残すため、端数で総資産が増減しません。

### PORTFOLIO GROWTH

通常結果と突発イベントの処理後、未取得のサテライト・長期方針からランダム3候補を提示し、1つ取得します。12年目は成長→カード報酬の順です。資産が尽きた場合は成長へ進まず、成長による救済はありません。サテライト2枠取得後は長期方針だけを提示し、獲得済み候補も除外します。

|長期投資方針|効果|
|---|---|
|生活防衛資金|生活トラブルの必要経費を10%軽減。既存の強制売却に追加ペナルティはないため、新設しません。|
|積立投資|取得翌年から年初に20,000円追加。そのうち投資へ10,000円、現金へ10,000円。|
|配当再投資|高配当株の配当の50%を投資へ戻す。高配当株未保有でも取得可能。戦略カードの配当金には適用しません。|
|現金管理|突発イベント終了後の現金比率が10%未満なら、翌年の開始時に現金10,000円を追加。10%ちょうどは対象外。|

各方針は重複取得不可です。金額・比率・成長年は `PORTFOLIO_CONFIG` に集約しています。年初の追加資金はショップより前に一度だけ適用し、20年目終了後には追加しません。成長時に現金管理を取得した場合、その年末の比率から判定します。

成長候補は専用の `growthRng` を使用し、既存の予報・相場・カード・突発イベントの乱数列を消費しません。セーブのキー・バージョン・読み書き方法は維持し、成長候補・取得内容・翌年の現金補充予約も保存します。古いセーブは追加フィールドを初期値で補い、旧仕様で選んだ高配当株・ゴールド・債券もそのプレイでは維持します。経過済みの成長イベントは遡って付与しません。

HUDのPORTFOLIOから比率と長期方針の詳細を開けます。スマートフォンでは成長候補を横スワイプして選びます。成績にはFINAL PORTFOLIOとLONG TERM STRATEGYを残します。資産保有年数はサテライトも含めて記録し、既存の称号条件そのものは変えていません。

### 検証とシミュレーション

既存69件＋追加15件の**84テスト**、`tsc --noEmit`、Pages静的ビルドと `/Roguelite/` アセット検証が通過しました。

```sh
node --experimental-strip-types scripts/simulate-portfolio.ts
```

600シード×42条件＝25,200プレイを比較しました。カードありの300万円到達率は33.0〜62.3%、カードなしは2.0〜24.0%。サテライトは下振れを和らげる一方、長期方針優先より目標到達率が低い傾向です。数値調整は行っていません。操作方針と比較限界を含む結果は [シミュレーション報告](docs/portfolio-simulation.md)、変更ファイルと確認範囲は [実装報告](docs/portfolio-growth-report.md) を参照してください。

暴落を含む既存10相場は通常のカード攻略対象です。これとは別に年末の突発イベントがあります。旧 `decision` フェーズと `REVEAL`・`DECIDE` 操作、確定前の損益プレビューは廃止しています。狼狽売り／ホールド／買い増しは市場ショック系の突発イベント専用です。売買計算ヘルパーは既存の計算回帰テスト用にも維持しています。

獲得カードは捨て札に入り、次のシャッフルから抽選対象になります。同種カードもインスタンスIDで区別し、削除は選択した1枚だけです。手札・デッキが0枚でも「このまま進む」で進めます。ショップは既存の価格・現金優先支払い・退出時の手札補充を維持しています。

`tests/normal-turn.test.ts` はカード単体での追加投資、選択解除、空の手札、二重処理防止、継続進行と100シードの20年完走を検証します。既存の計算・売買・ショップ・デッキのテストも維持しています。

## ローカル用ゲーム盤レイアウト

プレイ中は画面の高さ（100dvh）に合わせたHUD・盤面・メニューの3段構成です。PCでは下部の縦長手札の右に進行ボタンを置き、幅が狭い場合は手札の下に置きます。カード選択で浮き上がりと金色の発光を表示し、動きを減らす設定にも対応します。

資産グラフ・投資額の詳細・履歴は下部の「記録」から開きます。年末結果は簡潔なRESULT表示と詳細ダイアログに分けています。ショップはカード購入／カード削除のタブ式で、退出ボタンは常時表示します。

スマホでは手札・報酬カードを横にスワイプします。小さい画面や文字拡大では必要に応じて盤面の一部をスクロールでき、操作を切り捨てません。成績画面と詳細パネルには縦スクロールを許可しています。今回のレイアウト改修はローカル確認用で、サイトへのアップロード・公開更新は行いません。

## 年末の突発イベント

通常相場のRESULTにある「年末の出来事を確認」で発生判定を行います。発生すれば選択 → 結果を確認し、その後に対象年の成長／報酬／次の年へ進みます。20年目も判定し、最後のイベント結果を反映してからランク・称号を計算します。資産が尽きた場合は結果確認後にGAME OVERです。

- 発生可能な年の基本確率は30%。前年に発生した場合は必ず休みます。そのため全20年に対する実際の発生率は30%より低くなります。
- 残り年数と連続禁止を考慮し、20年完走時は最低4回を保証します。途中で資産が尽きたプレイは保証対象外です。同一イベントは1回までです。
- 市場・カード抽選とは独立したシード付き乱数を使用します。発生判定を二重実行せず、不正な選択や連打で再抽選できません。

15種類は `lib/game/incidents.ts` で管理します。

| 分類                  | 内容                                             | 処理                                                                                                                                                                |
| --------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 市場ショック（3種）   | 信用不安、緊急政策、薄商いの急変                 | この画面だけ狼狽売り／ホールド／買い増しを表示。選択後に騰落率を抽選。売りは急変前に投資90%を現金化、買い増しは現金50%を投入。翌年の再投資は既存の30%ルールを使用。 |
| 生活トラブル（10種）  | 怪我、家電、水漏れ、冠婚葬祭、ペット、引っ越し、端末故障、帰省、住まいの更新、想定外の税負担 | 必要経費は選択の余地なく支払います。現金優先、不足額だけ投資資産を強制売却。売却手数料・借金はなし。支払不能なら資産を0円で止めてGAME OVER。金額の決め方は下記。 |
| 日常／チャンス（6種） | 儲け話、落とし物、休日、勉強会、セール、臨時収入 | リスクと費用を文章で明示。任意の出費は手元現金が必要で、足りない選択肢は選択不可。無料で進める選択肢を必ず用意。                                                    |

日常の報酬は現金、カード（捨て札へ）、次回の予報精度アップ、次の通常相場の下落半減です。情報収集は次回予報の精度を70%から82%に上げ、確定した資産別の方向や騰落率は開示しません。下落半減は次の通常相場に1回適用し、上昇でもその年で終了。継続効果は重複せず、通常相場の処理で消費します。20年目は次回効果・獲得カードの使用機会がないことを表示します。市場ショックは年間の配当・戦略効果・通常相場の履歴を二重処理しません。

突発イベントの支払額・強制売却額・騰落率・獲得内容を結果画面と記録に表示し、資産グラフ・最大DD・最終資産にも反映します。WebMCPは `incident_choice`（`choiceId`）と `incident_next` に対応し、選択前の市場ショックの確定結果は公開しません。

`tests/incidents.test.ts` では2,000通りの発生スケジュール、支払優先順位、破産、選択ガード、ショックの売買順序、効果の期限、報酬・最終年の順序、履歴・グラフの整合性を検証します。

## 生活費と強制売却

生活トラブルの必要経費は固定額ではなく、`lib/game/expenses.ts` の `EXPENSE_CONFIG` で決まります。

- **年数別の基本額**：1〜5年目 5万〜12万円／6〜10年目 8万〜18万円／11〜15年目 12万〜25万円／16〜20年目 15万〜35万円。年が進むほど生活の規模も上がる想定です。
- **総資産による軽い補正**：`log2(総資産 / 100万円) × 10%` を基本額に掛けます。上下ともに±20%が上限で、資産が増えるほど請求も少し増えます。
- **想定外の税負担**（税イベント）：総資産の8%、下限8万円・上限30万円。ほかの生活イベントより抽選重みを低くしています。
- **生活防衛資金**（長期方針）を取得していると、必要額を10%軽減します。
- 金額は**イベントに遭遇した瞬間に1度だけ抽選**し、`currentExpense` として保存します。画面を読み直しても、セーブから再開しても再抽選されません。市場・カード・突発イベントとは独立した専用乱数を使います。
- 支払いは**現金優先**。不足したぶんだけ投資資産を売却します。個別資産の残高は持たないため、売却は**現在のコア／サテライト比率どおり**に行われた扱いになり、比率は変わりません。運用元本が減るので、以後の値上がり益と配当も減ります。
- 投資資産をすべて充てても足りない場合は、残高を0円で止めて結果画面を表示してからGAME OVERです。借金は発生しません。
- 支払い前は「請求額・基本額と資産補正の内訳・所持現金・不足額・売却される比率」を、支払い後は「支払額・うち強制売却額・現金と投資資産の増減」を表示します。

600シード×3コア×3操作方針×変更前後＝10,800プレイの比較は [`docs/expenses-simulation.md`](docs/expenses-simulation.md) にあります。強制売却の経験率は現金厚めで0.6%、標準で47.7%、追加投資優先で98.0%。標準方針の目標300万円到達率は51.8%→46.9%です。**この数値に合わせた追加調整はしていません。**

`tests/expenses.test.ts` は年数別レンジの境界、±20%の補正上限、現金内訳が請求額を変えないこと、税の上下限、防衛資金の一度だけ適用、現金で足りる場合の非売却、不足分だけの売却と整数円の整合、支払不能時の記録と終了順、比率を保った売却、強制売却後の配当減少、遭遇時に固定され再読込・セーブで再抽選されないこと、旧セーブの互換を検証します。

## UIの微調整と確認

戦略確定前に見せるのは、予報アイコンと**4つの観測材料（景気・市場心理・金利・ボラティリティ）だけ**です。予報分類の名前（強気予報など）は内部の抽選ロジック専用で、画面にもWebMCPの公開情報にも出しません。プレイヤーが材料を自分で解釈して戦略を決める形にしています。正確な騰落率は進行確定後のRESULTだけに表示します。カードを使わない進行は「このまま進む」に統一しました。

目標額は `GAME_CONFIG.targetAssets`（300万円）を共有し、総資産HUDに細い進捗バーと達成率を表示します。カード内は短い効果だけに絞り、全文はホバー時の説明・選択後の「詳細」に加えて、いつでも開けるデッキ一覧でも読めます（タッチ端末ではホバーが出ないため）。RESULTでは投資判断・使用戦略・保有資産の騰落率・総資産の前後を表示します。成績画面にはシードを表示し、同じ相場をやり直せます。

投資先の選択画面には、成長性・安定性・暴落耐性の5段階評価（`ASSET_RATINGS`）を表示します。個別の騰落率は並べず、資産どうしの相対的な違いだけを見せます。評価値はリターン表と配当率から自動算出するため、数値を調整しても表示が古くなりません。

PC（1440×900）、ノートPC（1366×768）、タブレット（820×1180・768×1024）、スマートフォン（390×844・375×667）をローカルブラウザの表示サイズ切り替えで確認しました。通常の相場・手札画面とRESULTで文言の重なりやページ全体の縦スクロールがないこと、長いカード名の折り返し、選択・詳細表示を確認しています。実機検証ではありません。前回のUI調整時の61テスト・lint・Pages静的ビルドとアセットパス検証も通過しています。

## 予報から先に戦略を決める通常相場

`lib/game/forecast.ts` に予報パターンと調整用の `FORECAST_CONFIG` を集約しています。

- `generateForecast()`：過去の相場と専用乱数で予報分類（強気・弱気・不透明・回復）を選び、その観測材料を返します。分類名は内部用で、公開するのは観測材料だけです。実際の相場はまだ決めません。
- `selectActualMarketEvent()`：戦略確定後、予報に沿う候補群／外れる候補群を抽選し、その中から相場を選びます。基本確率は70%、情報収集は+12ポイント（上限90%）。強気・弱気・回復の分類では株式相場の方向性の精度です。不透明分類の70%は停滞・インフレ・金利変動の候補群であり、上昇／下落の予測精度ではありません。
- `calculateMarketReturn()`：従来の資産別リターン表を基準に、共通の市場変動係数で±20%の範囲を抽選し、0.1ポイント単位で確定します。金額の整数丸め・資産特性は維持します。

予報と相場の乱数は、それぞれショップ・カード・突発イベントの乱数から独立しています。同じシードと選択を再現でき、カードの選び直しでは予報も相場乱数も変わりません。履歴補正は候補群内にだけ適用して予報精度を維持し、同じ相場が3回連続しないルールも維持します。デバッグの相場指定は `forcedEventId` に予約し、確定時にだけ適用します。

通常進行は `forecast` でカードを選び直し、`RESOLVE` 後は変更できません。元の予報を履歴に保存し、RESULTには「事前の市場観測 → 実際の相場」だけを並べます（予報が当たった／外れたという総合判定は表示しません）。破産したターンもRESULTを確認してから終了します。突発イベントの発生率・種類・支払い・選択順は従来通りです。

`tests/forecast.test.ts` は情報の非公開、旧操作の無効化、確定の一回性、各予報・履歴条件での確率分布、情報収集効果と期限、乱数の独立性、リターンの範囲、カードの利益上限と損失倍率、破産時の結果表示を検証します。既存テストは新しい進行に更新し、固定リターンでの売買計算の回帰検証も残しています。

## 数値バランスの調整根拠

以下はポートフォリオ成長導入**前**の単一資産版での調整記録です。今回これらの数値は変更していません。新システムでの結果は上記「検証とシミュレーション」を参照してください。

相場の重み・リターン表・ランク境界は、エンジンを直接回したシミュレーションに合わせて調整しています。調整前は株式の期待リターンがマイナス（S&P500を20年持つと中央値で×0.68）で、ゴールドが最もリターンが高く最も下落も小さい支配戦略になっていました。

- `MARKET_EVENTS` の `weight` は設計上の目標値です。`FORECAST_PATTERNS` の候補群にそれぞれ独自の重みを持たせ、実際の出現率が目標から大きくずれないようにしています（複数の予報に登場する相場が過剰に出る問題の対策）。実測との差は数ポイント残ります。
- 600シードで**配当を含む最終総資産の分布**を資産別に比較し、支配資産がないことを確認しています。カードなしで20年持ち切った場合は次のとおりで、**リターンの順位と安全性の順位がちょうど逆**になります。

  | 投資先 | 10%点 | 中央値 | 90%点 | 最大DD中央 |
  | --- | ---: | ---: | ---: | ---: |
  | S&P500（成長型） | 59万 | 153万 | 358万 | −38.5% |
  | NASDAQ100（攻撃型） | 39万 | 137万 | 479万 | −52.3% |
  | オルカン（バランス型） | 64万 | 129万 | 246万 | −31.5% |
  | 高配当株 | 70万 | 118万 | 175万 | −24.1% |
  | ゴールド | 81万 | 110万 | 147万 | −16.3% |
  | 債券 | 88万 | 106万 | 125万 | −11.4% |

- 高配当株は当初、配当込みで中央値・下ぶれ・最大DDのすべてがS&P500を上回る実質的な上位互換でした。値上がり側のリターンだけを下げ、「伸びは劣るが沈まない」位置に置き直しています。値上がりの遅さは、年1.5%の配当が現金として積み上がることで補います。
- オルカン（全世界株式）はS&P500より上値が軽く、そのぶん暴落での落ち込みが浅いバランス型です。初期選択の既定でもあります。
- 最終資産の中央値は、素直に20年持ち続けて約150万円（Bランク前後）、予報に応じてカードを選び分けて約290万円（Aランク前後）です。`RANKS` はこの分布に合わせています。
- 損切りの利益上限は+5%では常に期待値がマイナスだったため+14%にしました。市場ショックの資産感応度もゴールド・債券をやや引き上げ、守備資産がほぼ無傷になる状態を解消しています。
- この調整時点では投資先を開始時の選択で固定していました。現在もコアは固定し、複数資産の保有は成長イベントのサテライトで追加します。

再調整するときは、`lib/game/data.ts` の重みとリターン表、`lib/game/forecast.ts` の候補群、`lib/game/cards.ts` の `CARD_CONFIG` を変えたうえで、同じ手順で分布と最終資産を測り直してください。テストの期待値はリターン表から導出しているため、表を変えても壊れません。

## 既知の未対応

- Homebrew版Node.jsがx86_64、既存のネイティブ依存がarm64の場合は開発ツールが起動しません。今回、arm64のNode.js 24で既存依存をそのまま使用し、テスト・型チェック・Pagesビルド・ローカル画面確認を行えました。依存やlockfileの削除・再インストールは行っていません。
- 既存ファイルに未使用importとセーブ復元用Effectのlint指摘が残っています。今回の範囲外のため変更していません。詳細は実装報告を参照してください。
- 総資産0円によるGAME OVERは、レバレッジを多用したプレイ以外ではほとんど起きません（0〜3%）。緊張感は破産よりもランクで表現しています。
- 既存の現金を市場へ戻す手段は「ドルコスト平均法」「逆張り」と、市場ショックで狼狽売りした翌年の自動再投資です。新しい「配当再投資」は受領した高配当株配当の半額だけを対象にし、既存現金を自由に再配分する機能ではありません。
